# CLAUDE.md

`SwBridge` is a fully open-source (MIT) .NET abstraction of the SolidWorks COM API. It is **MCP-agnostic**: this repo must contain zero MCP, licensing, tier, or product code. If a change would be useless to someone building a non-MCP SolidWorks tool, it belongs in the `swmcp` repo instead. See the workspace-level `../CLAUDE.md` for the full boundary rules.

## Commands

```bash
dotnet build SwBridge.sln
dotnet test SwBridge.sln
dotnet run --project samples/SwBridge.Sample    # live smoke test — requires SolidWorks running
dotnet pack src/SwBridge/SwBridge.csproj -c Release -o ../localnuget
```

The pack output feeds `swmcp`'s local NuGet source (`../localnuget` at the workspace root) during development; the published package on nuget.org is the eventual real dependency channel.

## Architecture

- `SwDispatcher` — a dedicated STA thread with a work queue; `Run<T>(Func<T>)`/`Run(Action)` marshal arbitrary work onto it and block for the result, exception preserved. Every COM touch in the library — read and write alike — runs through it (`ADR 0003` in the workspace `docs/adr/`), so operations against one SolidWorks session are serialized by construction, not convention. No COM dependency itself, so it is unit-tested directly (ordering, exception propagation, reentrancy). **Reentrancy**: a `Run` call made from code already executing on the dispatcher thread (e.g. one SwBridge method calling another inside its own `Run`) executes inline instead of queueing — queueing would deadlock, since the only thread that could service the queue is the one now waiting; this is deliberately a composition mechanism (every public method can dispatch independently and still nest safely), not merely a deadlock guard.
- `SwConnection` — owns the `SwDispatcher` (`.Dispatcher`); lazy attach to the running `SldWorks.Application` via `oleaut32!GetActiveObject`, run on that thread; liveness-checks the cached RCW on every access and re-attaches if SolidWorks was closed/restarted. Never launches SolidWorks. `GetApp()` is still a direct, synchronous return of the raw `ISldWorks` — the deliberate raw escape hatch for advanced consumers — so a caller using it from a thread other than the dispatcher's own is doing the exact cross-apartment access `ADR 0003` exists to avoid; SwBridge cannot prevent that for raw consumers, only route its own calls correctly.
- `DocumentManager` — enumerate/resolve/open documents, plus `NewPart(templatePath?)` (creates from a template, or SolidWorks' configured default template via `swUserPreferenceStringValue_e.swDefaultTemplatePart` when omitted — the pattern verified live in `docs/seed-verification.md` §4.11). Every method wraps its body in one `Dispatcher.Run` call. Throws `SwNotRunningException` (rather than returning empty) so callers can distinguish "no SolidWorks" from "no documents".
- `SwDocument` — wrapper so consumers rarely touch interop types; raw `ModelDoc2` stays exposed via `.Model` (same raw-escape-hatch caveat as `SwConnection.GetApp()`). Every method dispatches via the `SwDispatcher` it was constructed with.
- `ModelInspector` — generic feature-tree reading. The central rule: **no feature type is hardcoded**. Callers pass a `Func<string, IReadOnlyList<string>?>` mapping feature type name → property names, and properties are read off `IFeature.GetDefinition()` by reflection (`ComPropertyReader`).
- `ComPropertyReader` — `Type.InvokeMember(..., GetProperty | IgnoreCase)` against late-bound COM objects; unreadable properties are reported as absent, never thrown. Read-only, by design (combined flags).
- `ComTypeInspector` — discovers the real members of a late-bound COM object, so a caller can find the member names/signatures to put in a `PropertySpec` instead of guessing. Two independent, complementary mechanisms:
  - `DescribeMembers` reads `ITypeInfo` reached via `IDispatch::GetTypeInfo`, falling back to `IProvideClassInfo` (which recovers real data for creatable coclasses like `ModelDoc2`/`PartDoc` — verified live, 175 members) since many SolidWorks objects answer `GetTypeInfoCount()` with 0 despite being dual interfaces. Some internal SolidWorks objects — notably `IFeature` and the feature-definition objects from `IFeature.GetDefinition()` — implement neither and are not introspectable at all this way (verified live against `Boss-Extrude1`'s `IExtrudeFeatureData2`); it returns an empty list for those, which means "not introspectable via `ITypeInfo`," not "no members" — `ComPropertyReader`'s name-based invocation still works on them.
  - `FindImplementedInteropInterfaces`/`DescribeMembersViaInterop` are the fallback that covers exactly that gap: they probe the live object with a real COM QueryInterface against every `[ComImport]` interface declared in the referenced `SolidWorks.Interop.sldworks` assembly (`typeof(ISldWorks).Assembly`, via `Type.IsInstanceOfType`), then reflect whichever interfaces actually matched. Verified live: this recovers `Boss-Extrude1`'s `IExtrudeFeatureData`/`IExtrudeFeatureData2`, including `GetDepth` as a method with 1 param. An unfiltered probe walks a few thousand interfaces (fine for an explicit discovery call, not a hot path); `ModelInspector.DescribeFeatureDefinition` filters to interface names containing `"FeatureData"` (~100 candidates) when it falls back to this after `DescribeMembers` finds nothing.

### Write surface (`ADR 0001`/`0002`/`0003` in the workspace `docs/adr/`)

- `ComInvoker` — the **only** write-dispatch door: `InvokeMethod`/`GetProperty`/`SetProperty`, each exactly one COM dispatch flag, **never combined** — the deliberate contrast with `ComPropertyReader`'s combined read-only flags. Returns a typed `InvokeOutcome { Success, Value, FailureDetail }` instead of throwing for a member-level failure, because SolidWorks write APIs report most failures as `Nothing`/`False`, not exceptions. Verified live: a `null` argument for a COM-interface-typed parameter (e.g. `SelectByID2`'s `Callout`) needs `new DispatchWrapper(null)`, not a bare `null` — late-bound `Type.InvokeMember` has no compile-time parameter types to coerce against, and a bare `null` marshals as `VT_EMPTY`, which SolidWorks rejects with `DISP_E_TYPEMISMATCH`.
- `ComPath` — open, dotted, read-only path resolution (`"Extension.SelectionManager"`) from an application or document root, one `ComPropertyReader` property-get per segment. Deliberately an open grammar, not a closed enum of known targets (`ADR 0001`): a bad path is a runtime `ComPathResult` failure, not a schema error, so a newly discovered manager object never needs a SwBridge release before it can be addressed.
- `ResultConverters` — `ToFeatureRef`/`ToSketchSegmentRef`/`ToSketchSegmentRefs` turn a live COM return into a plain, serializable DTO (`FeatureRef`, `SketchSegmentRef`) and release the RCW on the way out; a live interface pointer must never survive past the call that produced it. Verified live: `ISketchSegment.GetID()`'s interop signature says bare `object`, but it actually returns `int[]` (a composite id) — `SketchSegmentRef.Id` is that array's first element.
- `DocumentStateProbes` — cheap, targeted reads (`GetFeatureCount`, `IsInSketchMode`, `GetSketchSegmentCount`, `GetSelectionCount`, `NeedsRebuild`) plus one active probe (`RebuildSucceeded`, which forces `EditRebuild3()` since SolidWorks exposes no passive rebuild-error-count getter) — the vocabulary `ADR 0002`'s write-step verification and `ADR 0001`'s preconditions are built on. Take an already-resolved `ModelDoc2`; no dispatching themselves.

## Rules

- **No console output from library code** — consumers include stdio-based servers where stdout is a protocol stream.
- Public API avoids leaking interop types where practical; where they appear (`SwDocument.Model`, `SwConnection.GetApp()`, `ModelInspector` parameters) it is deliberate, for advanced consumers — and, per `ADR 0003`, using them off the dispatcher thread is the caller's own cross-apartment risk to manage.
- All COM access goes through `SwDispatcher`; do not touch a COM object from a thread you did not get via `SwDispatcher.Run`.
- Tests in `tests/SwBridge.Tests` must run **without** SolidWorks installed. Anything needing a live instance goes in `samples/` (currently `SwBridge.Sample`, which doubles as the manual smoke test; `--new-part` opts into the write-path demo, off by default so the sample stays read-only).
- Interop packages: `SolidWorks.Interop.SldWorks` / `swconst` 32.1.0 (SW 2024); supported floor is SolidWorks 2021+.
